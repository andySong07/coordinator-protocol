# Review: T-001 / round 1

## Summary

审查范围：`dab0849..87b85bb` 以及 87b85bb 时点的完整协议（`docs/protocol.md`、`docs/polling.md`、
`docs/repository-layout.md`、`templates/`、`examples/commit-message.txt`、`.collab/`）。同时覆盖
87b85bb 的 `Next: claude/reviewer review updated design and T-001` 所要求的 DESIGN-001 设计审查。

总体判断：Git 作为顺序/审计层、Markdown 作为语义层的分工合理；角色职责、普通技术分歧不升级给
用户的原则、最终用户确认门禁的意图都写得清楚。但作为“可被两个 Agent 自动执行”的协议，目前
仍有若干会导致状态无法判定、重复执行或安全门禁可被绕过的缺口，主要集中在：

1. project 生命周期与 task 生命周期混在一个状态机里；
2. task / comment 状态机缺少回退边与写入者约束；
3. commit 消费（ref、cursor、唤醒条件、崩溃恢复）不足以保证幂等；
4. coordinator 兼任 developer 时的分歧收敛独立性；
5. 用户最终确认的记录与失效规则、有损操作清单；
6. 多 subproject 时 cursor / lock / 角色键缺少 subproject 维度。

共 10 条 blocking、5 条 non_blocking。每条 blocking 都只要求可验证的结果，不限定实现方式。
